# Narrowing by drivetrain · 15 September 2026

One filter, added because the record earned it and not because the page had room for it.
Nothing about the tracker, the watchlist, `targets.json`, the ledgers, ranking or spicy-pick
semantics, shipping or financing arithmetic, the collection allocation, the API budget or the
private garage is touched. No provider call was made and the tracker was not run.

**Snapshot measured** `docs/data.json` SHA-256
`042936a4e3e13493ad58577ba10ed859208d96a0f10bee40cecfd401f5c642b5`, `generated` and

## The measurement, before any decision

`field_coverage()`'s docstring set the condition years ago: `seats` and `drivetrain` are kept
"so that 'three rows' and 'all-wheel drive' can one day narrow thirty-six models to six", and
"one real night decides whether those filters are worth building or whether the fields should
come back out." Twenty-four nights are on disk. Neither field was exported to `docs/data.json`
at all — 0 of 1,678 live and 0 of 1,676 departed entries, under any of seven spellings — so
the coverage question is asked of the CSV, which is where they are recorded.

| | drivetrain | seats |
| --- | --- | --- |
| known, live listings | **1,535 of 1,678 (91.5%)** | 1,297 of 1,678 (77.3%) |
| values present | AWD 894 · RWD 439 · FWD 201 | 5 ×1,067 · 7 ×132 · 4 ×62 · 6 ×34 · 2 ×2 |
| worst model | 73.3% (BMW i5) | **20.5% (Dodge Charger Daytona)** |
| models under 70% | none | six |
| models it splits | **18 of 21** | 4 of 21 |
| two different values ever recorded for one VIN | 2 (both EQB, FWD vs RWD) | 0 |
| impossible values | none found | a Lucid Air Pure recorded with 2 seats |
| independent cross-check | **0 contradictions over 389 listings whose trim encodes a drivetrain** (xDrive, eDrive, quattro, 4matic) | — |

Per-model coverage is reported because a high aggregate hides a model where the field is
unusable, and it did: seats is 91% on the Ioniq 9 and 21% on the Charger Daytona.

## The decision

**Drivetrain ships.** Coverage is broad and has no unusable model, the vocabulary is the three
words `drivetrain_of()` already folds to, unknown can stay unknown, and — the reason that
matters most — it **splits 18 of the 21 models carrying listings**. A filter that merely
restated the model the reader already picked would not narrow anything.

**Seats is deferred**, and 77% is not the reason. **17 of the 21 models record exactly one seat
value**, so the filter would largely repeat the model picker; one model is unusable at 21%; six
more sit at 67–70%; and at least one recorded value is impossible. The one place it genuinely
discriminates is 6-against-7 captain's chairs in the Ioniq 9 and the EV9 — 122 cars — where the
trim string already says so. What would reopen it: the Charger Daytona and the 67–70% band
climbing, and a reason to trust a value the trim does not corroborate.

## What shipped

The field is exported now, from the row colour and owners come from, for **live and departed
listings alike** — the comparison keeps a departed car, and a blank there would read as
ignorance about a car the record describes. The export was proved minimal before it was taken:
a rebuild of the **unchanged** tree reproduces the committed sheet **byte for byte**, and with
this change the diff over all 3,354 entries is exactly `+drivetrain` and nothing else, no other
field added, removed or changed, no top-level key touched. `docs/data.json` was regenerated by
`tools/rebuild_outputs.py` from the snapshot already on disk — no API call, no fetch.
**338 → 340 KB gzipped, 85% of the 400 KB budget**, which is unchanged.

The control is the existing `.sc-field` / `.sc-select` pattern beside *miles*: **Any · AWD ·
RWD · FWD · Not reported**. Persistence follows the device-preference model (`spicycar.prefs`),
an older profile with no key reads *Any*, and a stored value the vocabulary no longer offers is
dropped rather than left narrowing the page invisibly.

**The rule it keeps: a car with an unreported attribute is unknown, not a negative match.**
Asking for AWD sets the 144 unreported cars aside rather than failing them, says so in its own
sentence with the count — *"144 more cars could not be judged: the listing did not report a
drivetrain"* — and offers them in one press under *Not reported*, where the sentence changes to
say they are *"not cars recorded as something else — the source said nothing, so nothing is
claimed."* That is the difference between "known not to match" and "the source did not report",
in the reader's own words.

One branch in `passesShared()` — the single predicate the cards, the map, the plot, the counts
and the selected-car notice all read — so none of them can disagree about what is in view.
Measured after filtering: cards, map and plot all report the same 201 for FWD, with only the
plot's already-documented mileage omission named beneath it.

## The defect the fixtures found

`renderSelected()`'s escape hatch takes its label from `filterBits()`, so the moment drivetrain
became a bit the button read **"Clear AWD"** — and then cleared where, year, miles, accidents,
rentals, CPO, stock, budget and mission, every filter except the one it had just named. The car
it exists to bring back stayed hidden. `DISCOVERY.resetFilters` had been given `S.drive`; this
second reset path had not. Fixed, and pinned by NC-E below.

## Fixtures and negative controls

Six steps in the CI-wired `tools/browse_smoke.mjs`, on three named subjects shaped into a copy
of the record — one AWD, one RWD, one the feed never described — so the cases have subjects on
any snapshot. `docs/data.json` is never written by a test.

| Negative control | Check that went red |
| --- | --- |
| NC-A an unreported drivetrain is treated as a match | *and neither is the one nothing was reported for* |
| NC-B the set-aside sentence is not shown | *AWD names the cars it could not judge* |
| NC-C the choice is not persisted | *and it survived a reload that re-seeded nothing* |
| NC-D the filter replaces the mileage filter instead of composing | *FWD under 25,000 miles is the intersection* |
| NC-E the escape hatch names the filter and does not clear it | *only the reader's own press brings it back* |

All five turn their check red; each was restored from git and the restore proved by SHA-256.
NC-E is the defect above, found by the check before the control was written for it.

## Visual acceptance

Measured and looked at at 1280 and 390, light and dark, with the control focused by keyboard:

- **zero horizontal page overflow** at both widths, both themes;
- the label *Drivetrain* is visible, in the same lowercase field style as *miles* and *year*;
- `:focus-visible` true with a solid 2px ring; the select is 16px type, so a phone does not zoom;
- the *Show them* control is 88 × 44 px;
- the set-aside sentence reads at **5.29:1 (light) and 7.12:1 (dark)** in the page's ordinary
  muted text — `rgb(93,102,113)` / `rgb(146,160,177)`, **no warning colour**, because an
  unreported field is not an error;
- the first car card does not move (627 px at 1280, 607 px at 390, unchanged): the filter panel
  stays behind its existing toggle, so the shopping journey is not buried.

The select is 37 px tall, which is what every `.sc-select` on this page is; it was left alone
rather than made inconsistent with *year*, *miles* and *sort* beside it.
